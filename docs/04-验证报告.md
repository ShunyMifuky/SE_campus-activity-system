## 3. 发现的问题与修复（回归验证）

| 问题编号 | 发现的问题 | 原因分析 | 修改内容 | 受影响范围 | 回归验证结果 |
|---|---|---|---|---|---|
| **BUG-01** | 报名截止时间过后，学生仍可成功报名（TEST-05d） | `registration_service.signup()` 只校验了"名额未满"与"未重复报名"，把详情页"截止后隐藏报名按钮"当成了规则本身。按钮隐藏只是界面体验，直接向接口提交请求即可绕过 | 在 `signup()` 中增加截止时间校验：`now() > activity.signup_deadline` 时拒绝，并返回具体截止时间；同时补充注释说明"界面隐藏按钮不能当作规则" | `app/services/registration_service.py`，影响 REQ-05 报名与取消报名 | TEST-05a~05f 全部通过，报名记录数为 0 |
| **BUG-02** | 教师 B 可以编辑、下架教师 A 发布的活动，并可查看其报名名单（TEST-02c/02d/02e） | 约束 C3 要求"角色 + 资源归属"双重校验，实现时只做了角色校验（`@teacher_required` 回答的是"是不是教师"，回答不了"是不是你的活动"）。三个入口（编辑、下架、报名名单）都缺少归属判断 | 新增 `decorators.ensure_resource_owner()`，在 `activities.edit`、`activities.cancel`、`registrations.roster` 三处强制校验 `creator_id == current_user.id`，不匹配直接 403 | `app/decorators.py`、`app/activities/routes.py`、`app/registrations/routes.py`，影响 REQ-03、REQ-06 | TEST-02a~02e 全部通过，被越权访问的活动 `canceled_at` 保持为空 |

### 3.1 修复过程中的一次脚手架问题（非软件缺陷）

首次执行验证时另有 3 条用例（TEST-06a/06b/06c）失败。排查后确认**不是软件缺陷**，
而是验证脚手架的问题：测试类在请求之间长期持有同一个应用上下文，导致多个
`test_client` 共用同一个 `g` 对象，Flask-Login 缓存在 `g` 上的 `current_user`
发生串号，登录接口被"已登录"分支直接短路。

修正方式是让数据库访问使用短生命周期的应用上下文，不在请求之间长期持有。
该问题记录在此，是为了说明"验证失败不等于程序有错，需要先定位失败发生在被测对象还是验证手段"。

## 4. 验证结论

对照工程意图第 5 节的完成依据：

| 完成依据 | 结论 |
|---|---|
| E1 REQ-01 ~ REQ-06 可从界面完整走通 | **满足**。两个基本业务过程均完整走通：教师发布并管理活动、学生查看活动并报名 |
| E2 六条用例全部通过 | **满足**。30 条断言全部通过，其中 REQ-05 的四个拒绝分支（重复报名、名额已满、报名已截止、教师越权）逐一验证 |
| E3 服务重启后数据仍存在 | **满足**。SQLite 文件持久化，重新创建应用实例后数据可读 |
| E4 安全底线成立 | **满足**。数据库无明文密码；角色越权与资源归属越权均被拒绝 |
| E5 需求—设计—代码—验证可对应 | **满足**。每条需求在需求文档、设计文档、代码注释、Git 提交说明与验证用例中均可追溯 |

### 4.1 最终结论

**当前实现的软件达到了本组为 V1.0 确定的目标。**

V1.0 的建设目的是验证"校园活动的发布与报名可以收敛到一个统一的信息化载体中，
并且运行成本低到可以被日常使用接受"。验证结果表明：

1. 「教师发布活动 → 学生浏览并报名 → 教师查看报名名单」这条业务闭环真实成立；
2. 报名环节的关键业务规则（截止时间、名额上限、不可重复）在系统层面被强制执行，
   不依赖组织者的手工记忆；
3. 数据持久化在单文件 SQLite 中，无任何外部服务依赖，符合约束 C5。

### 4.3 本次验证未能覆盖的部分与风险

诚实记录，避免把"通过"当成"全面"：

1. **并发场景未验证**。防重复报名依靠"应用层校验 + 数据库唯一约束"双重保证
   （设计决策 D4），数据库约束这一层在单线程验证中未被真正触发，
   并发下的行为需要额外的并发测试才能确认。
2. **未做浏览器端到端验证**。验证通过 HTTP 接口完成，未覆盖 JavaScript 交互
   （如取消报名前的二次确认弹窗）与页面渲染效果。
3. **时间相关的边界未做穷举**。例如"报名截止时间恰好等于当前时间"、
   "活动开始时间与结束时间相同"等临界值未逐一构造。
